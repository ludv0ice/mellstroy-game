# Управление клиентами и тарифами — API 2.0

Реализация приложенного задания на Python 3.12+, FastAPI, Pydantic 2 и SQLite. Все исходники без комментариев.

## Структура

| Путь | Назначение |
| --- | --- |
| `app/main.py` | Приложение, Swagger, подключение маршрутов и обработка конфликтов |
| `app/manage.py` | Создание сотрудников из командной строки |
| `app/controllers/auth.py` | Вход и профиль |
| `app/controllers/clients.py` | Маршруты клиентов |
| `app/controllers/tarifs.py` | Маршруты тарифов |
| `app/core/config.py` | Путь к базе и ключ подписи токенов |
| `app/core/security.py` | JWT HS256, PBKDF2 SHA256, проверка ролей |
| `app/db/database.py` | Схема SQLite, соединения, внешние ключи |
| `app/models/schemas.py` | Модели запросов, ответов и правила валидации |
| `app/services/telecom.py` | Запросы, преобразование данных, проверка связей |
| `tests/test_api.py` | Интеграционные тесты с временными базами |

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.manage admin --role admin --full-name "Администратор"
python -m app.manage manager_ivan --role manager --full-name "Иванов Иван Иванович"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.manage admin --role admin --full-name "Администратор"
python -m app.manage manager_ivan --role manager --full-name "Иванов Иван Иванович"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Пароли вводятся скрыто, дважды, минимум 10 символов. Готовых учетных записей и паролей в репозитории нет. Сотрудников создает оператор с доступом к серверу: публичная регистрация отсутствует. PDF упоминает управление сотрудниками, но не задает для него HTTP-маршрутов; реализованы только документированные HTTP-операции.

Настройки находятся в `app/core/config.py`: `DATABASE_PATH` задает путь к базе, `JWT_SECRET` — ключ подписи токенов. Переменные окружения не используются. По умолчанию база создается в `telecom.db`, а `JWT_SECRET = None` включает случайный ключ на каждый процесс. После перезапуска приложения потребуется повторный вход.

Чтобы токены сохранялись между перезапусками, сгенерируйте ключ и запишите результат строкой в `JWT_SECRET` в своем локальном `app/core/config.py`. Один и тот же ключ должен использоваться всеми процессами приложения. Секретный ключ не публикуйте в репозитории.

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

JWT действует один час; роль при каждом запросе читается из базы.

Базовый адрес: http://localhost:8000/api/v1

Swagger: http://localhost:8000/api/v1/docs

OpenAPI: http://localhost:8000/api/v1/openapi.json

## Доступ

| Операция | Гость | Менеджер | Админ |
| --- | --- | --- | --- |
| Вход, список тарифов, общая статистика | Да | Да | Да |
| Профиль, чтение и создание клиентов, изменение клиента и его тарифа | Нет | Да | Да |
| Тариф клиента, количество на выбранном тарифе, тарифы с количеством | Нет | Да | Да |

## Маршруты

Пути указаны относительно `/api/v1`. В Swagger для закрытых маршрутов нажмите Authorize и вставьте токен из `/auth/login`.

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/auth/login` | `access_token`, `token_type`, `role` |
| GET | `/auth/me` | Текущий сотрудник без хеша пароля |
| GET | `/tarifs` | Все тарифы |
| GET | `/tarifs/by-client/{phone}` | Тариф клиента |
| GET | `/tarifs/stats/client-count` | Названия тарифов и число клиентов |
| GET | `/tarifs/{id_tarif}/client-count` | Количество клиентов выбранного тарифа |
| GET | `/tarifs/with-client-count` | Все поля тарифов с `client_count` |
| POST | `/tarifs` | Создание тарифа, 201 |
| PATCH | `/tarifs/{id_tarif}` | Обновление переданных полей тарифа |
| DELETE | `/tarifs/{id_tarif}` | Удаление тарифа, 204 |
| GET | `/clients?limit=20&offset=0&tarif_id=1` | `total`, `limit`, `offset`, `items` с тарифами |
| POST | `/clients` | Создание клиента, 201 |
| GET | `/clients/{phone}` | Полная карточка с тарифом |
| GET | `/clients/search/phone?phone=%2B7` | Поиск по префиксу телефона |
| GET | `/clients/sorted-by-birthday` | ФИО и дата рождения по возрастанию |
| GET | `/clients/search/passport-year?year=2015` | Паспорта, выданные после 2015 года |
| GET | `/clients/search/tarif-cost?minSalary=500` | Клиенты с тарифом строго дороже 500 |
| PATCH | `/clients/{phone}` | Изменение переданных полей клиента |
| DELETE | `/clients/{phone}` | Удаление клиента, 204 |
| PATCH | `/clients/tarif?phone=%2B79001234567&id_tarif=1` | Смена тарифа и полная карточка |

## Примеры тел запросов

`POST /auth/login`:

```json
{
  "username": "manager_ivan",
  "password": "ваш-пароль"
}
```

`POST /tarifs` с токеном администратора:

```json
{
  "tarif_name": "Основной",
  "internet": 50,
  "count_minutes": 500,
  "count_sms": 100,
  "salary": 600.25
}
```

`POST /clients` с токеном менеджера или администратора:

```json
{
  "number_phone": "+79001234567",
  "id_tarif": 1,
  "lastname": "Иванов",
  "firstname": "Иван",
  "patronymic_name": "Иванович",
  "date_birthday": "1990-05-15",
  "pasport_serial": "0012",
  "pasport_number": "003456",
  "date_issue": "2015-08-20"
}
```

`PATCH /clients/%2B79001234567`:

```json
{
  "lastname": "Петров",
  "id_tarif": null
}
```

Заголовок защищенного запроса:

```http
Authorization: Bearer <access_token>
```

## Валидация и решения по неоднозначностям PDF

- Сохранены имена полей документации: `firstname`, `pasport_serial`, `pasport_number`, `salary`.
- Полный телефон соответствует `^(\+7|8)[0-9]{10}$`. Префикс поиска начинается с `+7` или `8` и содержит до 10 следующих цифр. В PDF для поиска одновременно указаны префикс и маска полного номера; принят поиск по префиксу, чтобы работал поиск по коду страны. Записи с `8` и `+7` являются разными ключами, автоматически не преобразуются.
- В URL знак `+` передается как `%2B` или через `curl --data-urlencode`.
- Возраст 18–120 полных лет, даты не в будущем, выдача паспорта не раньше рождения. При PATCH повторно проверяется объединенная запись, включая старые даты.
- Фамилия и имя: 2–50 символов, буквы и дефис. Отчество можно не передавать или передать пустую строку.
- Серия и номер паспорта — строки из 4 и 6 цифр; начальные нули сохраняются.
- Название тарифа обрезается по краям, имеет 2–100 символов и уникально. Интернет 0–100000; минуты и SMS 0–10000; стоимость 0–1000000, максимум два десятичных знака.
- Деньги в SQLite хранятся целыми копейками, в JSON возвращаются числами. Фильтр стоимости строго `>`, фильтр года строго после 31 декабря указанного года.
- Неизвестные поля, явный null в обязательном поле и пустой PATCH отклоняются. `id_tarif: null` разрешен, в том числе для снятия тарифа.
- Статистика включает тарифы без клиентов. Удаление используемого тарифа возвращает 409: сначала смените или снимите тариф у клиентов.
- Приоритет прав взят из раздела «Роли пользователей»: удаление клиента доступно только админу, хотя пункт 3.9 перечисляет также менеджера.
- Опечатка `PATCH / /clients/tarif` исправлена на `/clients/tarif`. Ошибки в примерах валидации тарифа внутри раздела обновления клиента не перенесены: клиент проверяется по полям Client.
- 401 — нет действительного токена; 403 — недостаточно прав; 404 — запись отсутствует; 409 — конфликт; 422 — ошибка входных данных. Ошибки возвращаются в `detail`; для валидации тела, пути и query FastAPI формирует список с `loc`, `msg`, `type`.
