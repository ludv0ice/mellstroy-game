# Управление клиентами и тарифами — API 2.0

Реализация приложенного задания на Python 3.12+, FastAPI, Pydantic 2, SQLAlchemy 2, SQLite или PostgreSQL через psycopg 3. Все исходники без комментариев.

## Структура

| Путь | Назначение |
| --- | --- |
| `app/main.py` | Приложение, Swagger, подключение маршрутов и обработка конфликтов |
| `app/manage.py` | Создание сотрудников из командной строки |
| `app/controllers/auth.py` | Вход, профиль, cookie-сессия и выход |
| `app/controllers/clients.py` | Маршруты клиентов |
| `app/controllers/tarifs.py` | Маршруты тарифов |
| `app/core/config.py` | База, JWT, срок сессии и параметры cookie |
| `app/core/security.py` | JWT HS256, Passlib + Argon2id, cookie-сессии и проверка ролей |
| `app/db/database.py` | Engine, SQLAlchemy Session, создание таблиц и rollback |
| `app/models/entities.py` | ORM-модели тарифов, клиентов, сотрудников и сессий |
| `app/models/schemas.py` | Модели запросов, ответов и правила валидации |
| `app/services/telecom.py` | Запросы, преобразование данных, проверка связей |
| `tests/test_api.py` | Интеграционные тесты с временными базами |

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.manage admin --role admin --full-name "Администратор"
python -m app.manage manager_ivan --role manager --full-name "Иванов Иван Иванович"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.manage admin --role admin --full-name "Администратор"
python -m app.manage manager_ivan --role manager --full-name "Иванов Иван Иванович"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Пароли вводятся скрыто, дважды, минимум 10 символов. Готовых учетных записей и паролей в репозитории нет. Сотрудников создает оператор с доступом к серверу: публичная регистрация отсутствует. PDF упоминает управление сотрудниками, но не задает для него HTTP-маршрутов; сотрудники создаются через CLI. Дополнительно реализован выход из cookie-сессии.

Настройки находятся в `app/core/config.py`: `DATABASE_PATH` задает путь к базе, `JWT_SECRET` — ключ подписи токенов. Переменные окружения не используются. По умолчанию база создается в `telecom.db`, а `JWT_SECRET = None` включает случайный ключ на каждый процесс. После перезапуска приложения JWT с прежним случайным ключом перестанет работать. Cookie-сессии хранятся в базе и продолжают работать до истечения срока.

Чтобы токены сохранялись между перезапусками, сгенерируйте ключ и запишите результат строкой в `JWT_SECRET` в своем локальном `app/core/config.py`. Один и тот же ключ должен использоваться всеми процессами приложения. Секретный ключ не публикуйте в репозитории.

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

JWT и cookie-сессия действуют один час по умолчанию. Срок задается в `SESSION_SECONDS`; роль при каждом запросе читается из базы.

## PostgreSQL и сессии базы данных

`psycopg[binary]` — драйвер PostgreSQL. `SQLAlchemy` управляет подключениями и транзакциями. Для каждого запроса создается отдельная `Session`: изменения явно фиксируются через `commit()`, ошибки вызывают `rollback()`, сессия закрывается после запроса. Запросы используют ORM и параметры, а не строковую подстановку значений.

По умолчанию используется SQLite. Чтобы подключить существующую базу PostgreSQL, измените значение в `app/core/config.py`:

```python
DATABASE_PATH = 'postgresql+psycopg://telecom_user:your_password@localhost:5432/telecom'
```

Сервер PostgreSQL, базу `telecom` и пользователя с правом создания таблиц нужно подготовить отдельно. Таблицы создаются автоматически при запуске. Смена адреса подключения не переносит данные из SQLite в PostgreSQL. Для пароля со специальными символами используйте URL-кодирование. Не публикуйте настоящие учетные данные.

Существующий `telecom.db` продолжает использоваться: таблицы клиентов, тарифов и сотрудников сохраняются, добавляется `auth_session`. Автоматическое создание таблиц не заменяет миграции при последующих изменениях существующих столбцов.

## Пароли

Новые пароли хешируются через `passlib` алгоритмом Argon2id; реализация Argon2 предоставляется пакетом `argon2-cffi` и импортируется в Python как `argon2`. Отдельный пакет с названием `argon2` устанавливать не нужно.

Старые хеши PBKDF2 из предыдущей версии проверяются для совместимости. После успешного входа старый хеш автоматически заменяется на Argon2id. Пересоздавать сотрудников и удалять базу не требуется.

## Cookie-сессия входа

`POST /auth/login` теперь одновременно возвращает JWT и устанавливает cookie `telecom_session`. В базе хранится хеш случайного идентификатора сессии, ID сотрудника и время истечения. Повторный вход заменяет текущую cookie-сессию; истекшие записи очищаются при входе.

В Swagger достаточно выполнить `/auth/login`, после чего браузер автоматически отправляет cookie с последующими запросами к этому приложению. Вручную вводить cookie в Authorize не нужно. Для JWT можно по-прежнему вставить только `access_token` в поле HTTPBearer окна Authorize. Если переданы оба способа, приоритет имеет Bearer; неверный Bearer возвращает 401 даже при действительной cookie.

`GET /auth/me` работает с обоими способами входа. `POST /auth/logout` удаляет текущую cookie-сессию из базы и cookie из браузера. JWT остается самостоятельным токеном и действует до своего срока истечения; если он вставлен в Swagger Authorize, нажмите там Logout, чтобы прекратить его отправку.

Cookie имеет `HttpOnly` и `SameSite=Strict`. Для локального HTTP `SESSION_COOKIE_SECURE = False`; при работе через HTTPS установите `True`. Изменяющие запросы с авторизацией только через cookie требуют `Origin`, совпадающий с адресом приложения. Swagger в браузере отправляет его автоматически. Для HTTP-клиента с cookie добавляйте, например, `Origin: http://localhost:8000`; для Bearer этот заголовок не требуется. Межсайтовые изменяющие запросы отклоняются с 403. При работе через прокси настройте корректные внешний адрес и схему запроса.


Базовый адрес: http://localhost:8000/api/v1

Swagger: http://localhost:8000/api/v1/docs

OpenAPI: http://localhost:8000/api/v1/openapi.json

## Маршруты

Пути указаны относительно `/api/v1`. В Swagger выполните `/auth/login` для входа через cookie или вставьте полученный JWT через Authorize → HTTPBearer.

| --- | --- | --- |
| POST | `/auth/login` | JWT и cookie-сессия |

| GET | `/auth/me` | Текущий сотрудник без хеша пароля |
| GET | `/tarifs` | Все тарифы |

| POST | `/tarifs` | Создание тарифа, 201 |

## Валидация и решения по неоднозначностям PDF

- Сохранены имена полей документации: `firstname`, `pasport_serial`, `pasport_number`, `salary`.
- Полный телефон соответствует `^(\+7|8)[0-9]{10}$`. Префикс поиска начинается с `+7` или `8` и содержит до 10 следующих цифр. В PDF для поиска одновременно указаны префикс и маска полного номера; принят поиск по префиксу, чтобы работал поиск по коду страны. Записи с `8` и `+7` являются разными ключами, автоматически не преобразуются.
- В URL знак `+` передается как `%2B` или через `curl --data-urlencode`.
- Возраст 18–120 полных лет, даты не в будущем, выдача паспорта не раньше рождения. При PATCH повторно проверяется объединенная запись, включая старые даты.
- Фамилия и имя: 2–50 символов, буквы и дефис. Отчество можно не передавать или передать пустую строку.
- Серия и номер паспорта — строки из 4 и 6 цифр; начальные нули сохраняются.
- Название тарифа обрезается по краям, имеет 2–100 символов и уникально. Интернет 0–100000; минуты и SMS 0–10000; стоимость 0–1000000, максимум два десятичных знака.
- Деньги в базе хранятся целыми копейками, в JSON возвращаются числами. Фильтр стоимости строго `>`, фильтр года строго после 31 декабря указанного года.
- Неизвестные поля, явный null в обязательном поле и пустой PATCH отклоняются. `id_tarif: null` разрешен, в том числе для снятия тарифа.
- Статистика включает тарифы без клиентов. Удаление используемого тарифа возвращает 409: сначала смените или снимите тариф у клиентов.
- Приоритет прав взят из раздела «Роли пользователей»: удаление клиента доступно только админу, хотя пункт 3.9 перечисляет также менеджера.
- Опечатка `PATCH / /clients/tarif` исправлена на `/clients/tarif`. Ошибки в примерах валидации тарифа внутри раздела обновления клиента не перенесены: клиент проверяется по полям Client.
- 401 — нет действительного токена; 403 — недостаточно прав; 404 — запись отсутствует; 409 — конфликт; 422 — ошибка входных данных. Ошибки возвращаются в `detail`; для валидации тела, пути и query FastAPI формирует список с `loc`, `msg`, `type`.

## Проверка

```bash
python -m unittest discover -s tests -v
```

18 тестов проверяют роли, JWT, CRUD, фильтры, пагинацию, связи, валидацию, cookie-вход и выход, истечение и замену сессий, защиту Origin, сохранение сессии при перезапуске, rollback, Argon2id и обновление старого хеша. Для PostgreSQL проверяется загрузка диалекта psycopg; интеграционные тесты выполняются на SQLite. Живое подключение к серверу PostgreSQL в текущей среде не проверялось.
