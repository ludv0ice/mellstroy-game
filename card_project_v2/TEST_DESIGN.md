# Исследование тестовых данных

## Основание и решения по неоднозначностям

Основание: PDF «Задание. Проверка карты. Параметризация», включая приложение README.
Учебная [страница формы](http://188.234.244.32/0_checklist/Tests/2_2.html)
доступна и содержит четыре поля карты и таблицу классов эквивалентности.
Источником ожидаемых результатов unit-тестов являются правила PDF, а не реализация
учебной веб-формы. Браузерное тестирование формы не входит в это решение.

Выполнена дополнительная проверка Луна, поскольку она включена и в образец README.
Имя аргумента `holder_name` сохранено из кода PDF; `owner_name` в описании означает
то же поле. Не добавлены проверка текущей даты, BIN и запрет тестовых номеров:
эти требования отсутствуют. Нулевой четырехзначный год отклоняется как несуществующий;
двузначный `00` допускается как сокращение 2000 года. Для имени применяется `split()`:
различные пробельные разделители допустимы, сами слова проверяются строго по ASCII.

## Классы эквивалентности и граничные значения

| Поле | Допустимые классы | Недопустимые классы | Проверенные границы |
| --- | --- | --- | --- |
| Номер | 16 цифр с верной суммой Луна, без пробелов и с пробелами | Пустое значение, неверный тип, неверная длина, буквы, разделители, Unicode-цифры, неверная сумма | 15, 16, 17 цифр; неверная контрольная сумма |
| Имя | Два латинских слова в разном регистре; пробельные разделители | 0, 1, 3 слова; односимвольное слово; цифры, кириллица, акценты, дефис, апостроф, неверный тип | Длины слов 1 и 2 с проверкой обеих позиций |
| Дата | `MM/yy`, `MM/yyyy`, прошлая корректная дата | Месяц вне диапазона, неверные длины частей, неверный разделитель, буквы, Unicode, пробелы, неверный тип | Месяцы 00, 01, 12, 13; годы длиной 1, 2, 3, 4, 5; 0000, 0001, 9999; 00, 99 |
| CVV | Три цифры, включая начальные нули | Другая длина, знак, дробь, буквы, пробелы, Unicode, неверный тип | Длины 2, 3, 4; значения 000, 999 |
| Лун | Верная сумма для четной/нечетной длины, пробелы, примеры PDF | Неверная сумма, посторонние символы, неверный тип, слишком короткая строка | 1 и 2 цифры; умножение с результатом до и после 9 |

Представитель класса неверного типа для каждого валидатора: целое число JSON. Ожидается `False`.
Ожидаемые результаты заданы в JSON вручную по правилам, не вычисляются через `Card`.

## Общая проверка: только одно ошибочное поле

Эталон: `4111111111111111`, `JOHN SMITH`, `12/2030`, `123`.
В `full_card_cases.json` выбран один отрицательный пример для каждого поля:
меняется только это поле эталона. Метаданные `invalid_field` указывают его имя.

| Состояние номера | Состояние имени | Состояние даты | Состояние CVV | Общий результат |
| --- | --- | --- | --- | --- |
| Валидно | Валидно | Валидно | Валидно | True |
| Невалидно | Валидно | Валидно | Валидно | False |
| Валидно | Невалидно | Валидно | Валидно | False |
| Валидно | Валидно | Невалидно | Валидно | False |
| Валидно | Валидно | Валидно | Невалидно | False |

Это проверяет отказ при ошибке каждого поля; общая проверка вычисляет четыре результата и объединяет их через `all()`.
Тест `test_full_cases_have_at_most_one_invalid_field` проверяет, что действительно
меняется ровно одно поле, и что проверена ошибка каждого из четырех полей.

## Исследование попарной техники

Утверждение PDF об обязательном единственном ошибочном параметре является
ограничением данного задания. В общем случае pairwise требует покрытия всех пар
выбранных значений и допускает несколько невалидных параметров одновременно.
Здесь одновременно сохранено требование PDF и проведено полноценное попарное
исследование выбранных **валидных** значений.

Для состояний валидности с ограничением «не более одной ошибки» приведенные выше
пять строк покрывают все разрешенные пары: (валидно, валидно),
(валидно, невалидно), (невалидно, валидно). Пара (невалидно, невалидно)
исключена условием задания.

Для вариантов валидных значений выбраны следующие уровни:

| Поле | Уровень 0 | Уровень 1 |
| --- | --- | --- |
| Номер A | `4111111111111111` | `5555 5555 5555 4444` |
| Имя B | `AB CD` | `john smith` |
| Дата C | `01/30` | `12/2030` |
| CVV D | `000` | `999` |

Вместо полного перебора 16 сочетаний используется ортогональная таблица
из 8 строк с правилом `D = A XOR B XOR C`:

| JSON-кейс | A | B | C | D | Ожидается |
| --- | --- | --- | --- | --- | --- |
| pairwise-valid-01 | 0 | 0 | 0 | 0 | True |
| pairwise-valid-02 | 0 | 0 | 1 | 1 | True |
| pairwise-valid-03 | 0 | 1 | 0 | 1 | True |
| pairwise-valid-04 | 0 | 1 | 1 | 0 | True |
| pairwise-valid-05 | 1 | 0 | 0 | 1 | True |
| pairwise-valid-06 | 1 | 0 | 1 | 0 | True |
| pairwise-valid-07 | 1 | 1 | 0 | 0 | True |
| pairwise-valid-08 | 1 | 1 | 1 | 1 | True |

Каждая из шести пар столбцов AB, AC, AD, BC, BD, CD содержит комбинации
00, 01, 10, 11. Всего покрыты 24 уникальных парных сочетания.
Это автоматически проверяют шесть параметризованных запусков
`test_valid_pairwise_covers_every_value_pair`. Таблица не претендует на покрытие
всех классов невалидных значений pairwise: они исследованы отдельными тестами; в полных кейсах оставлено по одному отрицательному представителю каждого поля.

```bash
python -m pytest --cov=app/utils --cov-branch --cov-report=term-missing --cov-report=html:coverage_re --cov-fail-under=100
```

Результат: **72 passed**. В `app/utils/card.py` покрыты **47 из 47** исполняемых
строк и **18 из 18** ветвей; частично покрытых ветвей нет.
Порог `--cov-fail-under=100` выполнен. HTML-отчет создается в
`coverage_re/index.html` и исключен из Git по `.gitignore` из PDF.
100% покрытия подтверждает выполнение строк и ветвей, но не доказывает отсутствие
всех возможных ошибок: содержательную проверку дают выбранные классы и границы.
