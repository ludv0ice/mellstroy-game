# Card Project: Проверка данных банковской карты

## Описание

Проект содержит класс `Card`, который реализует валидацию данных банковской карты.
Предусмотрена проверка каждого поля отдельно и общая проверка всех данных одновременно.
Для тестирования используется `pytest` с параметризацией, JSON-данными и фикстурами.
Выполнено также дополнительное задание: алгоритм Луна.

Сохранены структура, класс `Card`, сигнатуры статических методов, класс `TestCard`
и схема Arrange/Act/Assert из PDF. Незавершенные методы реализованы, ошибки в
сигнатурах тестов исправлены. Параметризация перенесена в `pytest_generate_tests`,
который вызывает `metafunc.parametrize(..., indirect=True)`: каждый объект JSON
становится отдельным тестом, а фикстура `case` получает данные через `json_cases`.
Массивы с тестовыми значениями в Python не дублируются.

## Правила валидации

- **Номер карты (`card_number`)**: строка ровно из 16 цифр ASCII после удаления
  обычных пробелов; дополнительно должна проходить проверку Луна.
- **Имя владельца (`owner_name` в описании PDF, `holder_name` в его коде)**:
  ровно два слова, каждое из латинских букв `A-Z`/`a-z`, длина каждого больше 1.
  Метод `split()` допускает повторные и краевые пробелы, табуляцию и перевод строки
  как разделители слов. Дефисы, апострофы, акценты и кириллица не допускаются.
- **Срок действия (`expiry_date`)**: строго `MM/yy` или `MM/yyyy`, месяц `01`-`12`.
  Четырехзначный год находится в диапазоне `0001`-`9999`; `0000` не существует.
  Двузначный год `00`-`99` трактуется как сокращенная запись `2000`-`2099`.
  Пробелы и дополнительные символы запрещены. Проверка на истечение срока
  не добавляется: в PDF требуется корректность формата, месяца и года.
- **CVV (`cvv`)**: строка ровно из трех цифр ASCII, включая `000` и начальные нули.
- Все методы возвращают `bool`; неподходящий тип, в том числе `None`, возвращает `False`.
- `luhn_check()` принимает строку минимум из двух цифр с обычными пробелами.
  Проверка длины 16 выполняется в `is_valid_card_number()`, поэтому классический
  пример `79927398713` проходит только отдельную проверку Луна.

Лун проверяет контрольную сумму, а не существование карты. Дополнительных правил
платежных систем, например запрета номера из нулей, в задании нет.
Все тестовые данные вымышленные и не предназначены для оплаты.

## Установка

Требуется Python 3.10 или новее. Проверено на Python 3.12.14.
Все команды ниже выполняются из папки `card_project`:

```bash
cd card_project
python -m venv venv
```

Активация в Windows cmd:

```bat
venv\Scripts\activate
```

Активация в PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

Активация в Linux/macOS:

```bash
source venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Содержимое `requirements.txt` соответствует установленным при проверке версиям:

```text
pytest>=9.2.0
pluggy>=1.7.0
pytest-cov>=7.1.0
coverage>=7.17.2
pygments>=2.21.0
```

`pluggy` обеспечивает работу плагинов pytest, `pytest-cov` интегрирует `coverage`,
а `pygments` предоставляет подсветку синтаксиса.

## Запуск приложения

```bash
python -m app.main
```

Ожидаемый вывод: `Данные карты корректны: True`.

## Запуск тестов

```bash
# Все тесты в подробном режиме
python -m pytest -v

# Тесты конкретного файла
pytest tests/test_card.py -v

# Тесты конкретного класса
pytest tests/test_card.py::TestCard -v
```

Имена JSON-кейсов видны в отчете pytest. Используются только библиотеки
из `requirements.txt` и стандартная библиотека Python.

## Проверка покрытия кода

Команда из PDF:

```bash
python -m pytest --cov=app/utils --cov-report=html:coverage_re
```

Откройте `coverage_re/index.html`. Для проверки также всех ветвей и обязательного
порога покрытия используйте:

```bash
python -m pytest --cov=app/utils --cov-branch --cov-report=term-missing --cov-report=html:coverage_re --cov-fail-under=100
```

Результат проверки: **235 тестов успешно**, **100% покрытия** `app/utils`:
45 исполняемых строк и 18 ветвей, пропусков нет.
Из них 228 параметризованных проверок `Card` и 7 проверок свойств тестового набора.

## Классы эквивалентности, границы и попарное тестирование

Подробное исследование приведено в [TEST_DESIGN.md](TEST_DESIGN.md).
В `full_card_cases.json` каждый отрицательный пример содержит ровно одно
ошибочное поле, как явно предписано PDF. Дополнительно включена таблица из восьми
валидных строк, покрывающая все пары выбранных значений четырех полей.
Эти свойства автоматически проверяются в `tests/test_data_design.py`.
